# Integrated event comparison

Structured Compare accepts paired `context.integrated_combat.left` and `.right` scenarios. It adds selected, resolved stat rows once, then evaluates explicit direct and triggered packets against timed candidate mod state. The output is a conditional model, never a certified current-game winner. It is read-only and does not alter saved plans or ownership.

Each scenario must name four assumptions in `model_assumptions`: `scheduler=next_shot_interval`, `fire_rate_conversion=rpm_times_one_plus_bonus`, `pool_grouping=additive_within_named_pool_multiplicative_across_pools`, and `event_order=as_list`. Enter baseline pools for Weapon, Status, Elemental, All, Crit, Weakspot, Fire Rate, Reload Efficiency, Power Surge, Shock and Unstable Bomber on the shared Compare form. Enter `base_rpm`, `duration_seconds`, `magazine_capacity`, starting magazine and finite reserve rounds, an explicit `direct_packet`, and ordered events with stable IDs. Events may be `shot`, `wait`, `damage_taken`, `kill_enemy`, `reload`, or `triggered_packet`; reload needs supplied rounds and base seconds. If selected gear changes magazine capacity, enter the *final* capacity and set `magazine_capacity_is_final=true`. No rounding rule is inferred.

The packet states basis value, coefficient, Weapon or Status damage class, element or `none`, and optional exact keyword. Matching named pools apply; Crit and Weakspot eligibility remains unsupported in this scheduler. A `shot` consumes one magazine round. The next shot uses `60 / [base RPM × (1 + effective Fire Rate/100)]`; reload uses `base seconds / (1 + Reload Efficiency/100)`. Explicit trigger packets do not consume bullets. Duplicate event IDs are ignored; changed payload under an existing ID is rejected.

Candidate Covered Advance, Momentum Up and Ruthless Reaper rules require exact catalog ID, level, `allow_candidate=true`, and their semantic assumptions. The candidate numeric values are community level-unbound. Covered Advance state has a timed activation and expiry; Momentum phases affect the relevant subsequent packets and shot interval; Ruthless transfers only available reserve ammo after the stated kills. Candidate source hashes and selected row sources appear in the result. Separate candidate main-effect pool opt-in is rejected for the same candidate to prevent double count.

The model cannot infer weapon proc events, target defense, class, element, crit eligibility, unobserved main effects or current-level candidate strengths. A triggered packet requires explicit event timing and coefficient. Selected row gaps remain visible and may make the resulting damage subtotal incomplete. The scenario compares only what the entered event stream and named assumptions cover.

## Sourced weapon proc bridge

An integrated scenario may include `weapon_proc` with a bound `weapon_id`, `evidence_mode`, `model_mode`, stable `stream_id`, one `hit_inputs` entry per distinct scheduled shot, and a `damage_model` containing explicit Attack/Psi bases and packet models. Each hit input names `shot_event_id`, target, and required deterministic rolls and conditions. The selected alternative must include the same weapon identity, or mark the weapon scenario `independent_weapon_scenario=true` when comparing other gear. The latter is labeled independent, not part of a selected build.

The bridge schedules shots first, feeds those hit times and non-blast reload events to the dated weapon event runner, then inserts its resolved extra packets and periodic ticks into the timed state sequence. The runner's direct-hit packets are discarded so the scheduler counts each bullet once. Selected pools and active mod state are applied to sourced packets at their actual event times. A source packet with unknown class, element, coefficient, target count, or unsupported transforms stays unresolved; the complete modeled total becomes unknown while its known subtotal remains visible. Predator's sourced Weapon DMG ramp and Doombringer's timed Attack stack can affect subsequent eligible packets under the entered `weapon_state_order=after_direct_hit_before_triggered_packet` rule. Attack stacks need an explicit packet `basis_kind` for direct hits. Other source stat operators, basis ambiguity, and effects that would change the firing schedule remain unresolved rather than silently applied.

The timed scheduler's finite ammo and reload inputs remain authoritative. For Hazardous Object's sourced reload blast, enter `consume_remaining_magazine_for_blast=true`, `refund_outcome=none`, and explicit `thrown_reload_blast` target count and Weapon/Status class. The blast coefficient is computed from the actual remaining magazine before the entered reload loads any finite reserve rounds, using the dated source cap. The no-refund branch is a named scenario; refund destination and later ammo effects remain unresolved. An omitted consumption or refund assumption is rejected. The bridge does not treat independent Bernoulli rolls as verified game PRNG behavior.

The other six sourced packet timelines use the generic `weapon_proc.source_actions` hook. Each hit-kind action supplies `shot_event_id` and the source operator's target/charge inputs; the adapter replaces its time with the modeled shot time. Every eligible scheduled landed hit requires a hook. Only the three charged-shot families allow an explicit named `ineligible_shots` entry instead; the counter and every-hit families have no silent exclusion. Resource observations and orb ticks use an explicit `at`. `damage_model.basis_values` supplies Attack/Psi. `packet_hypotheses` keyed by source packet ID supplies only dimensions the dated source leaves unknown, such as Hammerhead's Weapon/Status class or Holographic Resonance's element. A hypothesis conflicting with a sourced dimension is rejected. See `PACKET_HOOK_COVERAGE.md` and `GET /api/weapon-timeline-coverage` for exact per-weapon fields and gaps. These bindings do not emit a complete timing stat modifier, so the scheduler does not invent one.
