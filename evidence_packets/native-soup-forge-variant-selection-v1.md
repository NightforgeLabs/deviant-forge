## What the crafting UI does

The readable path is `UIProduceDataModel.get_forge_item_list` → `BagHelper.get_forge_items_by_build_no_and_tab_icon_type` → `ForgeFormulaMgr.get_sel_type_formula_by_build_no`. The last method reads the server's `forge_season_no` and `disable_forge_no_list` template settings, walks candidate formula keys, resolves a matching tuple for an active forge season, and suppresses the scalar base row when an active override for that formula exists. It then applies disabled-formula, `valid_time`, hidden/display, and `ClientAvatar.is_memes_unlocked` gates before adding the result to the UI list. `ForgeDataHelper.get_forge_no_by_server_num` likewise returns the first matching `(1200379, season_no)` in supplied season-list order, otherwise the scalar base; absent `server_num`, it returns the base. `SeasonHelper.get_season_forge_season_no_list` supplies `(0,)` when no server number is supplied and normalizes an integer or tuple setting from server template data.

Thus, **conditional branch examples** with matching client candidates and all other gates passing are: forge-season list `[0]` → base row; `[0,1]` → tuple `1` row; `[0,222]` → tuple `222` row. If multiple override selectors are active, the generic resolver uses season-list order; UI listing also depends on its candidate keys and filters. No live `server_num`, active season list, disabled list, tech unlock or client candidate result was observed, so this packet does not claim which recipe Maurice currently sees. The installed UI method bodies are in `ForgeFormulaMgr.pyc` SHA-256 `3b69d300262832c4f63616c7d2ccfca224ba8dd569d11355c20677f70da8e3fb`; `SeasonHelper.pyc` SHA-256 `ab43b48e616d7bc77f57f639232a8d9a80258466728ff5c997dd6cce87e185e5`.
